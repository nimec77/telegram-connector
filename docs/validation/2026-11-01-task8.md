## Independent review and fixes

One independent whole-branch review of `fc4938a..a61de2c` found no Critical findings and three Important findings. All were reproduced before the fixes and resolved in one fix pass, followed by the full green suite. No Minor findings were deferred.

1. Mode 0600 alone left macOS allow-read ACLs intact. Disposable valid database/WAL/SHM fixtures now verify file ACL removal; access-granting directory ACLs are refused.
2. A 0700 parent beneath a writable ancestor could be replaced by another UID. The opener now verifies current/root ownership and protected permissions across canonical ancestry, permits root-owned sticky temporary roots, and uses the verified canonical path for SQLite. No secret-bearing file is created before ancestry rejection.
3. Metadata-only sizing removed the real next_cursor. Tight-boundary tests in both modes now verify that cursor bytes remain part of the metadata cap.

Ownership/ACL checks use existing trusted macOS utilities with captured output, suppressed stderr, kill-on-drop and a two-second deadline per invocation. No dependency was added. Existing directories are validated rather than repermissioned. Same-UID hostile filesystem mutation is outside this boundary. All permission fixtures were disposable; no real session was inspected or modified.

## Memory and latency measurements

The explicit benchmark uses the debug test binary and two concurrent ordered ten-item streams. Each synthetic JPEG is padded to the 20 MiB download cap. These are local fixture measurements, not live Telegram latency or a hard process RSS limit.

| Source fixture | Completed raw peak | Process peak RSS | Processing elapsed | Encoded outputs |
| --- | ---: | ---: | ---: | ---: |
| Initial 4096×4096 / 16 MP policy | 41,943,040 B | 634,273,792 B | 120,238 ms | 23,576,400 B |
| Final 4096×2048 / 8 MP policy | 41,943,040 B | 488,390,656 B | 59,505 ms | 11,794,240 B |

The measured RSS drove the final choice: 8,388,608 source pixels, 8192 per side and 64 MiB decoder allocation allowance. This retains UHD 3840×2160, 4096×2048 and 2048-square source support. A source whose only selected variant exceeds 8 MP is rejected as media_too_large. Raw slots reserve at most 80 MiB globally; decoded images, resize temporaries, output strings and allocator retention remain separate. The separate slow-first regression saturates all four production raw slots and proves a fifth input cannot start while completed buffers are retained. Cancellation tests prove started workers retain admission until exit.

## Decisions and limits

- Diagnostic history and keyed retention are separately bounded by configured entry capacity, preserving the direct diagnostic API without evicting pending reservations. Worst retained storage may therefore double relative to the previous single ring; each payload is still capped.
- The existing collected Rust batch method remains a compatibility adapter; callers own collected/cloned raw memory. Production MCP exclusively uses the lazy pipeline and holds its leases.
- Directory ACL policy deliberately rejects all access-granting ACEs, including harmless grants, instead of interpreting every principal/permission combination. Operators with such paths must select a private path or adjust the ACL explicitly; existing directory ACLs are preserved.
- Verification is macOS-only, as requested. Linux is owner-managed; Windows ACL behavior is unverified.
- Portable image bytes/associations and local rendering were verified. A configured third-party host UI and live Telegram/account behavior remain unverified; no target host/account was requested for a live smoke test.
- Completed Tasks 1–7/9 were preserved and exercised by the full suite rather than reimplemented. New evidence is scoped to this change.
- Raw admission and decoder allowance do not promise a hard RSS ceiling. The benchmark measurements above make that distinction explicit.
- Recovery keys prevent accidental selection mistakes and are not authenticated conversation isolation. Hostile same-UID file mutation is outside the storage boundary.
- Release publication and primary-branch integration remain separate from this local feature-branch handoff. Active design/plan files remain until merge, per repository policy.
