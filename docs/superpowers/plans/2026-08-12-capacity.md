# v0.16 "Capacity" Implementation Plan (B4, A4, A8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the documented `limit=100` usable on verbose channels: a response byte budget with truthful `has_more`, message-id cursor pagination (`before_id`/`after_id`), per-message text truncation (`max_text_length`), and a compact response format that hoists repeated channel metadata.

**Architecture:** Fetch loops in the Telegram client gain cursor support (grammers `offset_id` for `before_id`, a client-side stop condition for `after_id`) and report `has_more` truthfully (set only when an in-window, filter-matching message was refused by the limit). All response shaping — text truncation, compact hoisting, byte-budget fitting — happens at the MCP layer in a new pure module `src/mcp/tools/shaping.rs`, applied after the client returns and before `json_response`. The budget comes from a new `[limits]` config table and reaches the server via the existing builder-method pattern.

**Tech Stack:** Rust nightly (edition 2024), rmcp 3.1, grammers (Codeberg pin), schemars v1, serde, mockall.

**Spec:** `docs/superpowers/specs/2026-08-11-work-order-roadmap-design.md` §v0.16. Source audit: `docs/telegram-mcp-0.13.0-work-order.md` (B4, A4, A8).

## Design decisions fixed at plan time

These interpret the spec where it was silent; do not re-litigate during implementation:

1. **`after_id` is client-side.** grammers exposes `offset_id` (exclusive upper bound) on `MessageIter`/`SearchIter` but no `min_id` setter, so `before_id` rides the RPC and `after_id` is a break condition in the loop (same pattern as the existing time-window cutoff). Both bounds are **exclusive**: results satisfy `after_id < id < before_id`.
2. **Cursors are single-channel only** (spec: "get_recent_messages and single-channel search_messages"). Global search with `before_id`/`after_id` is rejected with a clear error. Budget-truncated global searches get `has_more: true` with **no** `next_cursor` (message ids are per-channel; a cross-channel id cursor would be meaningless).
3. **`has_more` means "more messages exist in the requested window/range"** and is set only when the fetch loop refused an in-window, filter-matching message because of the limit, or when the byte budget dropped messages. Window exhaustion (including hitting `after_id`) yields `has_more: false`.
4. **Compact mode is single-channel only in v0.16.** `format: "compact"` on a global search errors (the response-level `channels` map arrives with multi-channel requests in v0.18 per the roadmap). The header is derived from the first message; an empty result gets `channel: null`.
5. **Budget fitting is pop-until-fits** over the fully assembled response (truncation and compact applied first): serialize, and while over budget with >1 message, pop the oldest message and re-serialize. At most ~100 serializations of a ≤100-message response — a few ms, and byte-exact against the cap. **At least one message always survives**, even if it alone exceeds the budget (otherwise a caller could loop forever on the same cursor); this is the one documented way a response may exceed the cap.
6. **`max_text_length` counts characters** (`chars()`), not bytes — the corpus is Russian-language UTF-8 where bytes ≈ 2× chars; a byte cut could also split a code point. Truncation happens on the wire type (`MessageResponse`) only; the domain `Message` always carries full text.
7. **Shaping order:** truncate text → set limit-caused cursor → compact hoist → byte-budget fit. Budget must run last because it measures final bytes; it also recomputes `returned`, `has_more`, `next_cursor`, and (global search) `channels_in_results` after popping.

/// Response-size limits applied at the MCP layer (`[limits]`, work-order B4).
#[derive(Debug, Clone, Deserialize)]
pub struct LimitsConfig {
    /// Cap (bytes) on a serialized message-stream response. When exceeded,
    /// trailing messages are dropped and `has_more`/`next_cursor` are set.
    /// At least one message is always returned, even over-budget.
    #[serde(default = "default_response_byte_budget")]

    pub fn validate(&self) -> anyhow::Result<()> {

            anyhow::bail!("limits.response_byte_budget must be > 0");
        }
        Ok(())
    }
}

`src/telegram/client/ops_history.rs` — restructure the fetch loop to return `(messages, has_more)`:

```rust
        let (messages, has_more) =
            with_timeout("iter_messages", self.timeouts.history_secs, async {
                let mut messages = Vec::new();
                let mut has_more = false;
                let mut counter = PostCounter::default();
                let mut messages_iter = self.client.iter_messages(peer_ref);

                while let Some(msg) = messages_iter
                    .next()
                    .await
                    .map_err(|e| Error::TelegramApi(format!("Failed to iterate messages: {}", e)))?
                {
                    if let Some(to) = params.to_date
                        && message_timestamp(&msg).is_some_and(|t| t > to)
                    {
                        continue; // newer than the requested window; keep iterating toward it
                    }

                    // Check time filter - messages are in reverse chronological order
                    if message_timestamp(&msg).is_none_or(|t| t < cutoff_time) {
                        break;
                    }

                    // Apply media filter client-side (iter_messages doesn't support server-side filtering)
                    if params
                        .media_filter
                        .as_ref()
                        .is_some_and(|filter| !matches_media_filter(&msg, filter))
                    {
                        continue;
                    }

                    if let Some(converted) = convert_message(&msg, &peer) {
                        if params.collapse_albums {
                            // Post-level limit: stop only when a NEW post would
                            // overflow; trailing siblings of admitted albums pass.
                            if !counter.admit(album_key(&converted), params.limit as usize) {
                                has_more = true;
                                break;
                            }
                            messages.push(converted);
                        } else {
                            // Refuse the overflow message instead of pushing the
                            // limit-th and breaking blind: refusing proves a
                            // qualifying message exists beyond the page (A8).
                            if messages.len() >= params.limit as usize {
                                has_more = true;
                                break;
                            }
                            messages.push(converted);
                        }
                    }
                }
                Ok((messages, has_more))
            })
            .await?;
```

Then include it in the result: `Ok(SearchResult { returned, has_more, … })`.

```rust
/// Deserialize `Option<i64>` accepting either a JSON number or a numeric string.
///
/// The string form is trimmed before parsing. An empty/whitespace string or a
/// JSON `null` becomes `None`. Floats and non-numeric values produce an error.
pub fn flexible_opt_i64<'de, D>(deserializer: D) -> Result<Option<i64>, D::Error>
where
    D: Deserializer<'de>,
{
    #[derive(Deserialize)]
    #[serde(untagged)]
    enum NumOrStr {
        Num(i64),
        Str(String),
    }

    match Option::<NumOrStr>::deserialize(deserializer)? {
        None => Ok(None),
        Some(NumOrStr::Num(n)) => Ok(Some(n)),
        Some(NumOrStr::Str(s)) => {
            let trimmed = s.trim();
            if trimmed.is_empty() {
                return Ok(None);
            }
            trimmed
                .parse::<i64>()
                .map(Some)
                .map_err(|_| Error::custom(format!("expected an integer, got '{}'", s)))
        }
    }
}

//! Post-fetch response shaping at the MCP layer (work-order B4/A4/A8):
//! text truncation, compact hoisting, and byte-budget fitting. Pure
//! functions over wire types so every rule is unit-testable offline.

use crate::mcp::tools::types::responses::MessageResponse;

/// Default per-message text cap in characters (work-order B4).
pub(crate) const DEFAULT_MAX_TEXT_LENGTH: u32 = 2000;

/// Cut `text` to `max_chars` characters, flagging the cut. Counts
/// characters, not bytes: the corpus is largely Cyrillic UTF-8, where a
/// byte cap would halve the visible text and could split a code point.
pub(crate) fn truncate_text(msg: &mut MessageResponse, max_chars: u32) {
    let total = msg.text.chars().count();
    if total <= max_chars as usize {
        return;
    }
    msg.text = msg.text.chars().take(max_chars as usize).collect();
    msg.text_truncated = Some(true);
    msg.text_full_length = Some(total as u64);
}
```

`shaping.rs`:

```rust
/// Drop trailing (oldest) messages until the serialized response fits
/// `budget` bytes (work-order B4). Pop-until-fits: byte-exact against the
/// cap, and at ≤100 messages the repeated serialization costs a few ms.
/// At least one message always survives — a caller must never receive an
/// empty page with `has_more: true` for the same cursor, so a single
/// over-budget message is returned as-is (the one documented overrun).
/// After popping: `returned`, `has_more`, `next_cursor` (when
/// `cursor_eligible`), and `channels_in_results` (full format only) are
/// recomputed so the metadata stays honest (B6).
pub(crate) fn fit_to_budget(
    resp: &mut SearchResponse,
    budget: usize,
    cursor_eligible: bool,
) -> Result<(), String> {
    let mut popped = false;
    loop {
        let len = serde_json::to_string(resp)
            .map_err(|e| format!("Failed to serialize response: {}", e))?
            .len();
        if len <= budget || resp.messages.len() <= 1 {
            break;
        }
        resp.messages.pop();
        popped = true;
    }
    if popped {
        resp.returned = resp.messages.len() as u64;
        resp.has_more = true;
        if cursor_eligible && let Some(last) = resp.messages.last() {
            resp.next_cursor = Some(NextCursor { before_id: last.id });
        }
        let unique: std::collections::HashSet<i64> = resp
            .messages
            .iter()
            .filter_map(|m| m.channel_id.as_ref().map(|c| c.get()))
            .collect();
        if !unique.is_empty() {
            resp.query_metadata.channels_in_results = unique.len() as u32;
        }
    }
    Ok(())
}
```

**Paging and size (`has_more`, `next_cursor`, byte budget):** every
`search_messages` / `get_recent_messages` response carries `has_more`. It is

repetition. Single-channel scope only (`get_recent_messages`, or
`search_messages` with `channel_id`); an empty result keeps `channel: null`.
