# Telegram Workspace Services and Channel Streams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal** — Preserve the local connector and make the same Telegram account operations available to Rust callers, authenticated HTTP clients and remote MCP clients, with a native live channel feed.

**Architecture** — The root compatibility package and a stateful `telegram-api` share `telegram-core`. A separately deployable `telegram-mcp-http` delegates user operations to the API using exchanged credentials. Only the API opens hosted sessions and manages account-generation state.

**Tech stack** — Rust 2024, workspace resolver 3, pinned nightly, Tokio, grammers, Axum/Tower, SQLite and rmcp. Resolve external versions from the implementation-time inventory.

**Spec** — [Workspace services and channel streams](../specs/2026-11-19-workspace-services-and-channel-streams-design.md)

## Global constraints

- Retain the root package, `telegram_connector` Rust paths, `telegram-mcp` install and `--setup`, both stdio MCP protocol bindings, canonical and legacy results, 16 default tools and two opt-in canonical writes. Keep the single stdio tool router.
- Use one lockfile and one exact official Codeberg revision for the three direct grammers crates. Keep per-member features, nightly policy, workspace lints and external source, license and advisory coverage. Scope validation to macOS and use cached `--offline --locked` commands where possible.
- Validate locally before charging, and charge before each operation's first request-initiated Telegram RPC. Charge distinct attempted fan-out channels atomically, retain failed-channel charges, and settle media refunds exactly once. Preserve account budgets across idle eviction.
- Thread a cancellation token and absolute local deadline through each asynchronous stage. Preserve per-channel cursors, partial results, timeout flags, errors and the existing budgets. Keep secret-bearing material out of logs and response errors.
- Encode peer IDs as positive decimal strings, message IDs as positive JSON integers and timestamps as UTC. Preserve peer namespaces. Keep MCP input schemas self-contained under schemars v1 and keep canonical structured content equal to its JSON text fallback.
- Host one stateful API per data root. Derive the account from authenticated identity and bind work and handles to the link generation. Use distinct audiences, `telegram.read`, `telegram.send` and `telegram.link`, and default hosted sending to disabled.
- SSE starts live on every connection. Default to 20 channels per subscription, 4 subscriptions per account, 64 active account clients, 256 total subscriptions, 128 events or 1 MiB per subscriber queue, 64 KiB per encoded event, 64 MiB of queued bytes across the service, a 15-second heartbeat and a 10-second stalled-write deadline. Bound setup, idle eviction and total in-flight work through configuration.
- Run forward migrations on disposable fixtures. Keep unfurnished Telegram and identity-provider interoperability results separate from the mocked macOS gate. Implement in a feature checkout and review each task before integration.

## Review focus

- A retired session's cleanup resumes after its owner has relinked. It may address only the old generation, including after the 24-hour cleanup deadline. Task 6 pins the crash boundary.
- The same issuer user can have two registered clients with different grants. Exchanging a token must preserve the originating client and preserve or narrow scopes. Tasks 5 and 8 pin this boundary on both hops.
- A full pending listener or a reader that dies during head lookup must fail before headers and release every reservation. Tasks 9 and 10 pin this boundary.
- The largest Telegram message ID is included once, with no time cutoff or overflow. Task 7 pins the raw range and continuation behavior.
- An upload admitted before send revocation cannot dispatch after revocation wins the final check. Task 12 pins this race and the distinct already-dispatched outcome.
