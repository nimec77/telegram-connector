# Justfile for the Core Dev Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `justfile` at the repo root wrapping the core dev loop (build, test, fmt, clippy, run) with `just check` as the pre-commit gate, and mention it in `CLAUDE.md`.

**Architecture:** A single flat `justfile` with one recipe per command and `check` declared as a dependency chain (`fmt-check lint test`) — same fail-fast semantics as the documented `&&` chain. No Rust code changes; verification is behavioral (`just --list`, `just check`).

**Tech Stack:** `just` 1.52.0 (installed at `/opt/homebrew/bin/just`), cargo.

**Spec:** `docs/superpowers/specs/2026-06-12-justfile-design.md`

### Task 1: Create the justfile

**Files:**
- Create: `justfile` (repo root)

- [ ] **Step 1: Write the justfile**

Create `justfile` at the repo root with exactly this content. Note: recipe bodies are indented with 4 spaces (just accepts any consistent indentation; do not mix tabs and spaces). The comment above each recipe becomes its description in `just --list`.

```just
# List available recipes
default:
    @just --list

# Debug build
build:
    cargo build

# Release build
release:
    cargo build --release

# Run all tests
test:
    cargo test

# Run config tests serially (env var mutation)
test-config:
    cargo test config -- --test-threads=1

# Format all code
fmt:
    cargo fmt --all

# Check formatting without writing
fmt-check:
    cargo fmt --check

# Clippy with warnings as errors
lint:
    cargo clippy -- -D warnings

# Pre-commit gate: fmt-check + clippy + all tests
check: fmt-check lint test

# Run the MCP server binary
run:
    cargo run --bin telegram-mcp
```

- [ ] **Step 2: Verify the justfile parses and lists all recipes**

Run: `just --list`

Expected output (`just --list` sorts recipes alphabetically by default):

```
Available recipes:
    build       # Debug build
    check       # Pre-commit gate: fmt-check + clippy + all tests
    default     # List available recipes
    fmt         # Format all code
    fmt-check   # Check formatting without writing
    lint        # Clippy with warnings as errors
    release     # Release build
    run         # Run the MCP server binary
    test        # Run all tests
    test-config # Run config tests serially (env var mutation)
```

If `just --list` errors, fix the syntax error it reports before proceeding.

- [ ] **Step 3: Verify bare `just` shows the same listing**

Run: `just`

Expected: identical output to Step 2 (the `default` recipe runs `just --list`).

- [ ] **Step 4: Verify the serial config-test recipe**

Run: `just test-config`

Expected: `cargo test config -- --test-threads=1` runs and all config tests pass (output ends with `test result: ok.`; some tests filtered out is normal).

- [ ] **Step 5: Run the pre-commit gate through the justfile**

Run: `just check`

Expected: `cargo fmt --check` produces no diff, `cargo clippy -- -D warnings` finishes with no warnings, `cargo test` ends with all suites reporting `test result: ok.` Exit code 0. This may take several minutes (full build + test run).

If any stage fails, the failure is pre-existing or a justfile bug — diagnose before committing (the tree was clean at branch time, so a clippy/test failure most likely means the recipe invokes the wrong command).
